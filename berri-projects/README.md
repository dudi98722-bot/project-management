# BERRI — ניהול פרוייקטים

מערכת לניהול פרוייקטי בנייה מול לקוחות וקבלני משנה, עם ניהול קופות והוצאות.
כל הנתונים נשמרים בגוגל שיטס — לשונית לכל טבלה, כך שהגיליון עצמו הוא הגיבוי המלא.

**כתובת:** https://berri.dudi-ananalytics.com

---

## מה יש במערכת

| מסך | מה רואים בו |
|-----|-------------|
| **תמונת מצב** | יתרה בכל הקופות, חובות לקוחות, יתרות לקבלנים, רווח צפוי, וכל הפרוייקטים הפעילים בטבלה אחת |
| **פרוייקטים** | דוח כללי: מחיר ללקוח, מחיר לקבלן, צפי והוצאות בפועל, רווח, ורווח לחודש — לכל פרוייקט |
| **פרוייקט בודד** | תמונת מצב מלאה + שלוש טבלאות: תשלומי לקוח, תשלומים לקבלן, הוצאות |
| **קופות** | יתרה בכל קופה, כרטסת עם יתרה מצטברת, והזנת כסף שנכנס/יצא/הועבר בין קופות |
| **דוח יומי** | לאן זז הכסף ביום או בטווח תאריכים — בחלוקה לקופות, עם יתרת פתיחה וסגירה |
| **הוצאות עסק** | הוצאות ללא שיוך לפרוייקט, עם פילוח לפי קטגוריה |
| **הוצאות בית** | הוצאות פרטיות — מנהל בלבד |
| **דוחות** | סיכום כללי, תזרים לפי חודשים, וחובות פתוחים משני הצדדים |

בכל טבלה: סינון בראש כל עמודה, מיון בלחיצה על הכותרת, שורת סיכום, ייצוא לאקסל — וייבוא מאקסל.

### ייבוא מאקסל
כפתור **📥 ייבוא** בכל טבלת תשלומים, הוצאות ותוספות. קובץ xlsx או csv, או הדבקה ישירה מאקסל.

1. **קובץ** — השורה הראשונה היא שורת כותרות
2. **מיפוי** — המערכת מזהה לבד איזו עמודה היא מה לפי שם הכותרת, ואפשר לתקן
3. **בדיקה** — כל שורה מוצגת לפני הייבוא, עם הסיבה אם היא לא תיקלט
4. **ייבוא** — רק השורות התקינות, במנות של 100

* פרוייקט וקופה מזוהים **לפי שם** — גם שם חלקי ("כהן" ← "וילה משפ׳ כהן"), כל עוד הוא חד-משמעי
* שם קופה שלא נמצא **עוצר את השורה** — כסף שנכנס בשקט לקופה הלא נכונה משבש את היתרה
* תא קופה ריק ← הקופה שנבחרה בחלון הייבוא
* תאריכים: `24/09/2026`, `24.09.26`, `2026-09-24`, או תא תאריך של אקסל
* **כפילויות מדולגות** — שורה שכבר קיימת במערכת (אותו תאריך, סכום ופרוייקט) לא תיובא שוב,
  אלא אם מסמנים במפורש. כך קובץ שמועלה פעמיים בטעות לא מכפיל סכומים
* בתוך דף פרוייקט — אין צורך בעמודת פרוייקט; כל השורות נכנסות אליו

## איך מחושב הרווח

```
רווח צפוי = מחיר ללקוח − מחיר לקבלן משנה − הוצאות
```
* **הוצאות** — בפרוייקט פעיל: הגבוה מבין צפי ההוצאות למה שהוצא בפועל
  (כדי שהרווח לא ייראה גבוה מדי לפני שההוצאות הוזנו). בפרוייקט שהסתיים: מה שהוצא בפועל.
* אם הלקוח שילם יותר מהמחיר, או שלקבלן יצא יותר מהמחיר — נלקח הסכום הגבוה, והמערכת מתריעה.

```
רווח ממוצע לחודש = רווח צפוי ÷ משך הפרוייקט
```
המשך נמדד מתאריך ההתחלה עד תאריך הסיום. בפרוייקט שעוד רץ — עד היום.

**קיזוז מקבלן משנה:** בהוצאה לפרוייקט אפשר לסמן "לקזז מקבלן המשנה".
ההוצאה נזקפת על חשבון מה שמגיע לו, ולא על חשבון הרווח — היתרה לתשלום יורדת בסכום ההוצאה.

## התקנה

### 1. השרת (Google Apps Script)
1. גיליון חדש בגוגל שיטס בשם **"BERRI — ניהול פרוייקטים"**
2. בגיליון: **תוספים ← Apps Script**. למחוק את הקוד הקיים, להדביק את
   `berri-projects-AppsScript.gs`, לשמור
3. **Deploy ← New deployment ← Web app**
   * Execute as: **Me**
   * Who has access: **Anyone**
4. **Deploy** ← לאשר הרשאות
5. להעתיק את כתובת ה-`/exec`

### 2. הטמעת הכתובת
ב-`core.js`, בשורה של `DEFAULT_GS_URL`, להדביק את הכתובת בין הגרשיים.
כך אף משתמש לא יצטרך להזין אותה.

### 3. העלאה לשרת
```bash
ssh root@64.176.175.180 "bash /tmp/deploy-berri.sh"
```
עדכון אחרי שינוי (לפי SHA של הקומיט, לא main — יש CDN cache).
הרשימה נלקחת מ-GitHub עצמו, כך שקובץ חדש לא נשכח בחוץ; כל קובץ נכתב לקובץ זמני
ומוחלף רק כשההורדה הצליחה, כדי שהאתר לא יישאר עם קובץ חצי-כתוב:
```bash
SHA=<SHA>
for f in $(curl -fsSL "https://api.github.com/repos/dudi98722-bot/project-management/contents/berri-projects?ref=$SHA" \
           | grep -o '"name": *"[^"]*"' | cut -d'"' -f4 | grep -v -E '\.(gs|md)$'); do
  curl -fsSL "https://raw.githubusercontent.com/dudi98722-bot/project-management/$SHA/berri-projects/$f" -o "/var/www/berri/$f.new" \
    && mv "/var/www/berri/$f.new" "/var/www/berri/$f"
done
```

### 4. כניסה ראשונה
בכניסה הראשונה המערכת מבקשת להגדיר מנהל — שם משתמש וסיסמה.
מיד אחרי זה נוצרות שתי קופות (מזומן ובנק) וקטגוריות התחלתיות, שאפשר לשנות בהגדרות.

**עדכון קוד השרת בעתיד:** להדביק מחדש ב-Apps Script, ואז
**Deploy ← Manage deployments ← עריכה ← Version: New version ← Deploy**.
הכתובת נשארת אותה כתובת.
